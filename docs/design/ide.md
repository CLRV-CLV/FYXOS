# FYX IDE 设计

> 目标：**比 VS Code 更强的自研 IDE**，且不是 VS Code 的衍生品。

---

## 1. 为什么能比 VS Code 强

VS Code 的根本约束：Electron（Chromium + Node）→ 冷启动慢、内存占用高；
扩展运行在**同一进程**里，一个差扩展拖垮全局；语言智能靠各家扩展自行实现，
质量参差。

FYX IDE 的四个结构性优势：

| 维度 | VS Code | FYX IDE |
|---|---|---|
| 运行时 | Electron（Chromium+Node） | 原生（自研 `fyx-ui` + 系统合成器），无 Web 运行时 |
| 冷启动 | 1–3 s（大工程更久） | **< 200 ms**（工程索引后台增量加载） |
| 内存（大工程） | 1.5–4 GiB | **目标 250–600 MiB**（数据存列式 + mmap，按需分页） |
| 扩展隔离 | 同进程，可拖垮主程序 | **每扩展独立进程 + 能力最小化**；崩溃只影响自己 |
| 语言智能 | 每语言一套扩展（LSP 各自实现） | **内核级的统一索引服务** `fyx-indexd`，全语言共享 |
| 多光标/大文件 | 大文件卡顿 | 基于 **piece table + 持久化 B 树**，GB 级文件秒开 |
| 与 OS 集成 | 外挂 | 直接吃 FYXOS 的快照/权限/内容寻址：全局撤销、跨应用回滚 |

## 2. 架构

```
┌────────────────────────────────────────────────────────┐
│  UI 层        fyx-ui（声明式、GPU 合成、120Hz）         │
├────────────────────────────────────────────────────────┤
│  编辑内核     fyx-edit（piece table、CRDT 协作、       │
│               增量渲染、多光标、矩形选择）              │
├────────────────────────────────────────────────────────┤
│  语言服务     LSP-F（对 LSP 的精简+增强）+ fyx-indexd   │
├────────────────────────────────────────────────────────┤
│  构建/调试    fyx build 集成 · fyx-debug（自研调试器）  │
├────────────────────────────────────────────────────────┤
│  扩展宿主     每扩展一个沙箱进程（IPC + capability）    │
└────────────────────────────────────────────────────────┘
```

### 2.1 统一索引服务 `fyx-indexd`

**这是"更强"的核心**：全局唯一的符号索引，跨语言、跨工程、常驻、增量。

- 基于**内容寻址**：以文件 BLAKE3 为 key，未改动的文件永不重新解析
- 索引结构与 `.fyx` 的存储层共用 → 装包即带索引（可选），首次打开大型依赖
  无需等待
- 查询 API 统一：

```
fyx-index query --symbol=HttpRequest --kind=type --scope=workspace
fyx-index refs  --at=src/main.rs:42:17
fyx-index callers --symbol=parse_header --transitive
```

- 语言解析器以 `.fyx` 包形式接入（`provides: indexer/rust`），仍跑在沙箱里
- **跨语言跳转**：Rust 调 C 的 FFI、C++ 调 Python 的绑定、SQL 查询与
  ORM 定义之间都能跳（靠索引里统一的符号 URI：`fyx-sym://crate/path#item`）

### 2.2 LSP-F：对 LSP 的增强

保留 LSP 的兼容性（现有语言服务器可直接接入），并扩展：

| 增强 | 说明 |
|---|---|
| 结构化增量同步 | 不做整文件重发；发的是编辑操作序列 |
| 批量并行请求 | 一次拿完整个文件的诊断/高亮/折叠，减少往返 |
| 语义令牌持久化 | 令牌缓存在索引服务，滚动时不重算 |
| 能力协商更细 | 客户端声明渲染能力，服务端不必重复计算 |
| 崩溃隔离 | 语言服务器崩溃自动重启，UI 不闪、不丢未保存内容 |

### 2.3 调试器 `fyx-debug`

- 自研，内核提供原生调试接口（复用 `ptrace` 风格的 `FYX_DBG_*` 系统调用）
- 支持：**时间旅行调试（rr 式记录/回放）** —— 这是超越 VS Code 的关键能力
  - 内核记录非确定性的来源（系统调用、线程调度点、信号）
  - 回放时可后退、可任意设断点重跑
- 反向单步、数据断点（watchpoint）、并行栈视图（按锁/通道分组协程）

## 3. 扩展模型

### 3.1 沙箱与权限（复用 `.fyx` 的 `perm`）

扩展安装时声明能力，UI 上以**人类可读**的方式展示：

```toml
[extension]
name = "git-lens-like"

[perm]
read_workspace = true
write_workspace = false
net = ["api.github.com:443"]
exec = ["git"]
ui  = ["status-bar", "inline-decoration"]
```

- 扩展**默认无网络、无写权限**
- 越权调用在**内核/服务层**被拒，并在 UI 上给出可见的告警条目
- 扩展进程 CPU 超限或崩溃 → 自动降级/隔离，主界面不受影响

### 3.2 扩展 API 的原则

- **声明式优先**：能描述就不写过程代码（主题、语法、菜单、键位、片段）
- **不可变快照**：扩展读到的是工作区在某一版本的快照，避免竞态
- **可撤销**：扩展对文件的批量修改统一登记，可一键 `undo`

## 4. 功能清单（对标并超越）

### 4.1 编辑

- 多光标 / 矩形选择 / 多光标列编辑
- 超大文件（GB 级）秒开、秒存（piece table + mmap）
- **跨文件重构**：重命名符号、改函数签名、提取函数/变量/接口，全工作区一次改完
- **语义合并**：三向合并时理解语法树与符号，冲突率显著低于文本合并
- 结构化的"折叠与大纲"、面包屑、缩略图（minimap 带语义着色）

### 4.2 导航

- 全局符号/文件搜索（走 `fyx-indexd`，毫秒级，支持模糊匹配与缩写 `dmc` → `DocumentManagerController`）
- **调用图/依赖图可视化**（可按模块折叠、按变更集高亮）
- 跳转到定义/声明/实现/类型定义/测试
- 打开过的上下文按**任务**分组（不是按文件列表）

### 4.3 调试与性能

- 断点（条件/命中次数/日志点）、观察表达式
- **时间旅行调试**（见 2.3）
- 内置性能剖析：CPU 采样火焰图、内存分配热点、锁竞争视图
- 与 FYXOS 的系统级剖析器打通（可一路下钻到内核函数）

### 4.4 版本控制

- git 深度集成（阶段 K 移植）
- **语义 diff**：按函数/类型显示变更，而非按行
- 变更集与 IDE 状态（打开文件、断点、未保存缓冲）绑定 → 切分支不丢上下文
- 与系统快照打通：可把"当前工作区 + 依赖版本"整体存为一个可回滚快照

### 4.5 协作

- 内置 CRDT 实时协作（自研，不依赖中心服务；可选自托管中继）
- 参与者各自的光标/选区、跟随演讲者、共享终端（只读/可写可选）
- 离线编辑后合并无冲突

### 4.6 AI 辅助（可选、可关闭、可本地）

- 默认**本地模型**，不强依赖网络；可选接入远程
- 以索引为上下文（不是把整个仓库塞进提示词）→ 更准、更快、更省
- 所有建议标注来源（"来自 src/net/http.rs:120 的同类写法"）
- 生成代码的改动统一走 `undo` 记录，可整体撤销

## 5. 性能预算

| 场景 | 目标 |
|---|---|
| 冷启动到可编辑 | < 200 ms |
| 打开 50 MB 源文件 | < 150 ms |
| 全局符号搜索（100 万符号） | < 30 ms |
| 输入到渲染（P99，120Hz） | < 8 ms |
| 常驻内存（10 万文件工程） | < 600 MiB |
| 保存 10 MB 文件 | < 40 ms（CoW + 异步刷盘） |

## 6. 分阶段落地

| 阶段 | 内容 |
|---|---|
| L1 | `fyx-ui` + 编辑内核 + 语法高亮（tree-sitter 风格的自研增量解析器） |
| L2 | `fyx-indexd` + LSP-F + 基础跳转/补全/诊断 |
| L3 | `fyx-debug` + 时间旅行调试 |
| L4 | 扩展宿主与 SDK、git 深度集成 |
| L5 | 协作、性能剖析、AI 辅助 |
