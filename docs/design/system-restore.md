# FYXOS 系统还原设计

> **实现状态（2026-10-23）**：CoW 快照、跨重启回滚、快照历史保留和默认
> 保留 `/home` 已经实现并通过 ATA 断电测试，详见
> [`fyxfs.md`](fyxfs.md)。本文其余内容仍包含长期目标；B 树、内容寻址、A/B
> 内核槽、独立救援镜像、认证和自动策略不应被视为已经交付。
>
> 目标：类似 Windows"系统还原"，但**更快、更彻底、更可控** ——
> 快照是 O(1) 的、可随时回滚到任意历史点、可只回滚系统而不动个人文件、
> 且**崩溃后一定能进得去**。

---

## 1. 底座：FYXFS 的写时复制

系统还原不是一层外挂工具，而是文件系统的原生能力。

- FYXFS 是一棵 **B 树 + 内容寻址** 的 CoW 树
- "快照" = 对某棵子树的根指针做一次**引用**；创建快照 O(1)、几乎瞬时、初始
  不占空间
- 之后的写入只分配新块、改路径上的指针，旧块被快照引用着就不会回收
- 空间增长 = 两次快照之间**实际变化的数据量**（经压缩后通常几十 MiB 级）

```
时间 ────────────────────────────────────────────►

根@T0 ──► [CoW 树 A]
              │  写入
根@T1 ──► [CoW 树 A'] ◄── 快照 T1 仍指向 A
              │  写入
根@T2 ──► [CoW 树 A''] ◄── 快照 T2 仍指向 A'
```

## 2. 三类快照

| 类型 | 触发 | 保留策略 | 可回滚范围 |
|---|---|---|---|
| **自动** | 装/卸/更新包前、系统更新前、每天一次、每次启动后 10 分钟 | 保留最近 7 天 + 每周一个共 4 个 + 每月一个共 12 个 | 系统 + 应用 |
| **手动** | 用户 `snapshot create --name=…` 或 UI 上"打个还原点" | 永不自动删除（除非用户删） | 可选：仅系统 / 含个人文件 |
| **启动守卫** | 连续两次启动失败时自动生成 | 保留最近 3 个 | 系统 |

**关键设计：个人文件默认不进系统快照。**
`/home`、`~/Documents` 等位于独立子卷，系统回滚时**完全不动**。
用户可在打快照时显式选择包含（例如"发布前全量快照"）。

## 3. 子卷布局

```
/                        @root        系统，可回滚
├─ /usr                  @usr         系统，可回滚
├─ /var                  @var         可变数据，可回滚
│   └─ /var/lib/fyx      @pkgdb       包数据库（与快照强一致）
├─ /opt                  @opt         可回滚
├─ /home                 @home        个人文件，默认不回滚
│   └─ ~/Documents       @docs        个人文件
├─ /snapshots            @snap        快照元数据（自身不参与快照）
└─ /boot                 独立分区     引导器 + 内核（内核有 A/B 双槽）
```

**内核 A/B 槽**：更新内核写入备用槽，启动成功才标记为 good。
内核起不来 → 下次自动回退到上一槽。这样"更新后开不了机"这一最常见的
灾难场景被彻底消除。

## 4. 回滚语义

### 4.1 三种粒度

```console
$ rollback system                 # 只把系统子卷回退，个人文件不动
$ rollback system --to=T2         # 回到指定快照
$ rollback package fyx-editor     # 单个包回退（依赖树一并回退）
$ rollback file /etc/fyx/net.toml # 单个文件回退到上/任意快照版本
```

### 4.2 原子性

回滚 = 改子卷指针 + 重启。

1. 写入 `pending-rollback` 意图记录（持久化）
2. 切换子卷指针（单次原子写）
3. 重启
4. 启动早期若发现 `pending-rollback` 未完成 → 依据意图记录继续完成

任何时刻掉电都不会处于"半回滚"状态。

### 4.3 冲突处理

回滚时若检测到 `/home` 中的配置比快照**新**且已被用户修改：
- 默认**保留用户版本**，并生成一份 `<file>.fyx-new` 供比对
- UI 上明确列出这些文件，可逐个选择"用快照的"或"保留我的"

## 5. 崩溃可恢复性（最重要的一条）

"还原功能"本身必须永远可用，哪怕系统已经起不来：

1. **启动守卫**：连续两次启动失败 → 引导菜单自动出现
   "上次启动失败，进入还原" 选项（10 秒倒计时后自动进入）
2. **救援镜像常驻**：`/boot` 分区里放一个极小的 `fyx-rescue`（≤ 8 MiB），
   它只依赖内核的最小子集（当前内核 Shell 就是它的雏形），提供：

```console
fyx-rescue> list snapshots
fyx-rescue> rollback system --to=T5
fyx-rescue> check disk /            # 校验并修复
fyx-rescue> mount @home /mnt        # 挂载个人文件以便拷出
fyx-rescue> shell                    # 进入完整内核 Shell（当前 37 条命令）
```

3. **离线还原介质**：`fyx image --rescue` 可生成 USB 镜像；
   从 U 盘启动后能挂载任意 FYXFS 卷并回滚

## 6. 与包管理器的协同

- 每次 `add/remove/update package` 前**自动**打快照（O(1)，无感）
- 包数据库与文件系统快照**同一事务**：不存在"包装了但文件没换"的中间态
- `undo` 命令 = 回滚到上一个自动快照（终端级与系统级统一语义）

---

## 7. 资源开销

| 项目 | 开销 |
|---|---|
| 创建快照 | O(1)，< 1 ms |
| 快照初始占用 | 0 字节 |
| 典型日增量（压缩后） | 30–150 MiB |
| 保留 30 天的典型总量 | 0.8–2.5 GiB（按内容去重后） |
| 回滚耗时 | 一次重启（+ 指针切换 < 1 ms） |
| 后台开销 | 空闲时做去重与压缩，CPU 限流 ≤ 3% |

配额：默认快照总占用不超过卷容量的 **10%**，超出时按"自动快照由旧到新"
淘汰（手动快照永不自动淘汰，但会告警）。

---

## 8. 安全

- 快照**只读**挂载，防止恶意程序篡改历史
- 快照元数据带**链式哈希**（每个快照含上一个快照的哈希）→ 历史不可伪造
- 回滚需凭证（用户密码 / 生物识别）；救援模式回滚需**物理在场**（或恢复密钥）
- 勒索软件防护：检测到短时间内大量文件被改写 → 自动落快照 + 通知用户
  （配合 `perm.fs.write` 白名单，未授权写入本来就被拒）
